## P0：诊断20B拒判

先区分四种现象，不能全归为同一种Boundary：

| 现象 | 判断依据 | 处理 |
| --- | --- | --- |
| 计划目标确实缺失 | 人工确认该必需组分未被任何任务承诺 | 标missing |
| 真正语义不确定 | 描述或研究口径不足，人类复核后仍有合理分歧 | 保留uncertain，进入Boundary |
| 证据提取失败 | 原文有明确承诺，模型却无法定位相应引用 | 单独记录提取失败，不归因于计划缺失 |
| 模型无信息拒判 | 给定明确任务及标准，仍全uncertain或不能给出有效判断 | 记录拒判及协议问题，不证明计划本身模糊 |

小实验采用单因素比较，每次固定同一输入、标准、模型与其余参数：

1. 抽取任务：只定位原文研究承诺，不做covered/missing决策，观察是否能够读取并复制文字。
2. 呈现对照：原任务JSON与按字段分句的等内容版本；不按答案挑选引用，不附期望标签。
3. 提示对照：明确解释「证据=计划承诺的原文，不是已经执行研究所得的数据」，与当前提示比较。
4. 输出模式对照：统一JSON Object模式，再检查是否影响拒判；单次结果不能据此确定原因。

每条件建议至少3次观察，保留所有输出。记录模型实际ID、输入与提示指纹、参数、终止原因、原文引用和拒判理由。不要同时换模型、改标准、改呈现再把变化归因于单一因素。原因分析没有人工支持时仍标为假设。

## P0：准备24个固定候选与人工金标

目标规模24个：4个主题，每题6种候选，包含完整、关键遗漏、部分覆盖、语义冗余、同义表达但完整、合理模糊边界。它们是样本设计，不是预先认定的答案。

先由人类确认题目scope及必需组分，再进行独立标注与分歧裁决；记录标注者、日期、理由和版本。两名标注者的合理分歧允许保留uncertain，不能为了凑二分类样本强行裁决。AI可以辅助起草，不得代签或自动设置human_reviewed。

按整个主题预留3题开发、1题保留检查；同题变体不跨分组。小规模预留组也不是充分泛化证明。候选类别和模型身份应对标注者隐藏；实际Core/Boundary数量由人工结果决定，不能按构造意图强行设定。

**当前24样本人工金标准尚未建立。** 在金标完成之前，不报告准确率、误拒率或漏判率；已有的模型标签只用于诊断。

## P1：统一比较20B与120B

使用同一冻结标准、同一输出定义与匿名计划，尽可能统一输出模式和预算，记录未能统一的因素。比较的是具体模型/配置组合，不只归因于参数规模。评测模型不看反馈或期望答案。

以「需要修复」为阳性，只在人工Core样本上计算二分类指标；uncertain是拒判，不是第三种确定真值：

| 指标 | 明确分母 |
| --- | --- |
| 条件准确率 | 人工Core中，模型给出确定决策的样本；必须同时报告决策覆盖率 |
| 全Core正确决策率 | 全部人工Core；拒判不算正确，防止靠拒判刷高准确率 |
| 误拒率 | 人工认可的合格Core样本中，被模型错误判需修复的比例 |
| 漏判率 | 人工认可的需修复Core样本中，被模型错误判可通过的比例 |
| 拒判率 | 全部人工Core中的uncertain比例，另按合格/需修复分别报告 |
| 技术失败率 | 请求失败、截断、格式错误、无效引用分别记录；不当成uncertain |

人工Boundary另报模型强判、拒判和澄清行为，不进入主要二分类准确率。证据提取失败、真实歧义、无信息拒判及技术失败保持分类，不能把它们都删除后只报告成功子集。

验收阈值必须在实验前由项目负责人明确冻结，当前不虚构准确率或误拒率目标。金标不足或分母为零时报告不可计算，而不是100%。

## P1：分层评审离线模拟

金标比较完成后，离线模拟20B初筛，仅将uncertain交120B，与单独20B和单独120B比较。120B仍可以uncertain；未决样本不强迫通过/拒绝，也不接入在线阻断。特别检查20B的高置信错判是否被分层路径漏过，不能只看转交的样本。

## P2：成本与延迟

统计全部调用的token、转交率、技术失败、重试、端到端延迟分布与超时；缺失用量不填0。使用当时服务的真实计费与账户条件核算成本，未取得信息不估算成零。小样本延迟仅为观察值，不宣称稳定性能。

只有在覆盖识别、错误识别、拒判及运行成本都经过验证后，才讨论是否值得生产投入。核心验收问题：满足要求时能否稳定确认覆盖，缺失时能否准确定位缺失，而不是继续换更强模型或增加功能。
