# Web 任务正文证据接入

本轮优化适用于显式 Web 模式、`web.evidence.v1` profile，并需要启用
`ENABLE_EVIDENCE_WEB=true`。开关默认值保持不变；普通兼容 Web 路径和
GitHub 采集路径继续使用现有入口。

## 执行顺序

搜索候选 → 共享页面采集 → 按任务意图选择段落 → 任务摘要 → 批量 claim
判断 → 摘要修复或现有缺口补搜 → 汇总已选证据 → 报告质量检查与生成。

证据 Web 模式向搜索后端传递 `fetch_full_page=False`，由已有
`WebCaptureService` 统一负责正文读取。若适配器已经返回正文，仍可复用该内容。

## 证据复用

- `PreparedResearch.web_evidence` 持有当前运行的页面缓存与已选证据集合。
- 规范化后的同一请求 URL 使用独立锁，多个任务及补搜重试复用同一次采集结果。
  不同 URL 可并行读取；等待同一页面时检查取消状态。
- 每个任务按自身查询及意图重新选段落，不复用其他任务的相关性选择。
- 任务证据沿用报告侧 `stable_evidence_id`，使用一致的截取原文和段落定位。
- 最终汇总读取已选证据集合并持久化原有快照，不再次发起页面采集。
- 抓取失败保留 `metadata` 等级及原因；摘要和 Judge 提示明确区分搜索摘要与正文。

缓存仅在当前运行内有效；不同入口 URL 重定向到同一页面的情况尚未合并。
已失败的 URL 本轮运行内也复用失败结果，新的查询仍可寻找其他来源。

## 段落选择与预算

使用英文词项及中文双字词项的重合度，结合章节标题进行确定性排序；它只判断
阅读相关性，不判断事实支持关系。每页最多选择 3 段，每次任务检索最多 12 段，
为最相关段落保留一个相邻段落位置。长段落使用相关原文窗口，长度受 profile
的 `max_excerpt_chars` 限制（当前 Web profile 为 1,200 字符）。

共享证据按原文窗口去重后占用运行级预算，已使用的证据可在预算耗尽时复用。
原有页面大小、段落提取数量、请求预算及受控网络访问限制继续生效。

## 验证

`test_web_task_evidence.py` 覆盖页面尾部与相邻段落、长段落窗口、追踪参数 URL
去重、并发复用、运行隔离、取消、预算耗尽及 metadata 降级。
`test_evidence_pipeline_integration.py` 验证两个任务的摘要与 Judge 在正文
采集后运行，且最终报告保留相同证据 ID、片段和定位，不重复采集。

本轮未引入 embedding 服务，也未扩展最终覆盖检查的补搜调度。
