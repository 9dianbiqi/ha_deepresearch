# Planner 语义反馈实验：一个成功的配对案例

日期：2026-10-08。生成模型：glm-4.7-flash；评审：Codex（本次聊天AI）。

## 结果

**本主题的一次成功配对中，明确语义反馈补足了对照计划遗漏的盈利压力及未来情景/风险。** 第二次反馈重复请求及重试均因供应商1305失败，稳定收益尚未得到验证。

| 指标 | 无语义反馈对照 | 两条语义反馈 |
| --- | --- | --- |
| 成功观察数 | 1 | 1 |
| 任务数 | 6 | 6 |
| 格式解析 | fenced JSON成功 | fenced JSON成功 |
| 四轴AI评审：相关性 | 全部直接相关 | 全部直接相关 |
| 四轴AI评审：冗余 | 未发现确定重复 | 未发现确定重复 |
| 四轴AI评审：粒度 | 合理，数量在3–6建议内 | 合理，数量在3–6建议内 |
| 完整维度覆盖 | 2/4：share、policy | 4/4 |
| 确定性Plan Gate | pass | pass |
| 词法覆盖 | 0.5789 | 0.7105 |
| 输入tokens | 1116 | 1270 |
| 输出tokens | 394 | 419 |
| 总tokens | 1510 | 1689 |
| 本次观察耗时 | 4.719秒 | 3.078秒 |

反馈增加179 tokens（11.9%），其中输入增加154、输出增加25。这里只报告token量，没有换算费用。反馈组这次耗时更短不能证明延迟优化，可能受缓存、服务端状态和随机性影响。

两个成功计划均通过词法门禁，而无反馈组仍漏了两个复合维度，继续显示词法通过与语义完整不同。

## 具体变化

### 对照组

任务：市场规模/技术结构、品牌份额、价格与定价、政策、技术/出口驱动、企业战略。

价格任务只调查价格、终端优惠及定价；没有明确盈利压力。增长任务只列当前技术与出口动力；没有明确未来预测、情景或风险。市场规模与品牌份额分别研究总体和品牌层级，可形成不同结论，不判重复。

### 反馈组

任务：市场份额、价格竞争与盈利压力、政策、增长驱动、未来情景与风险、企业战略。

- 价格任务明确研究价格竞争对利润、毛利率、整体盈利能力的影响，query也包含这些目标。达到了本轮pricing标准；具体成本分解仍可更细。
- 新增未来增长情景与风险任务，明确预测2026–2027年需求，识别下行风险及不确定性。
- 把市场规模和品牌份额合并为一个任务，为风险任务腾出位置，任务总数仍为6。
- 驱动任务与情景/风险任务相互补充，共同完成growth，而不是要求所有子目标塞进同一任务。

15个任务对均给出AI互补理由，没有确定重复或显式不确定；这不是经过校准的置信度或人工金标准。技术例子依然需要检索验证，不能因出现在计划中就当作行业事实。

## 设计与预注册

- 冻结原主题、原系统提示词、原基础用户prompt与日期，不在运行时重新取日期。
- 同模型、temperature=0、max_tokens=2000、timeout=45秒、thinking关闭。
- 两组都看到同一份旧计划JSON，防止把“看到旧计划”的作用误归因于反馈。
- 对照只看到共同旧计划与基础prompt；干预另加两条反馈：盈利/成本压力，未来情景/预测/下行风险。
- 反馈标题明确为AI离线评审意见，没有冒称原计划被确定性门禁拒绝。
- 每次调用清空历史，不把对照或上一次干预输出带入下一次。
- 运行前记录share、pricing、policy、growth的检查项。维度按计划整体覆盖，互补任务可共同满足复合维度；不是简单匹配词语，也不要求每个参与任务独自完成整维度。
- 不运行检索、报告、profile任务截断或自动门禁重试。

历史原始计划只作背景，不作为当前对照：历史输入没有共同的旧计划JSON。实际比较使用本轮新生成的对照计划。

## 全部请求与失败

本轮计划1个对照、2个反馈重复。另做一次失败对照尝试以及一次针对失败反馈的重试：

1. 首次对照请求失败：429 / 1305。
2. 新运行的对照成功。
3. 同运行的反馈1成功。
4. 同运行的反馈2失败：429 / 1305。
5. 只重试反馈2，再次失败：429 / 1305。

共5个逻辑LLM调用，2成功、3供应商失败；SDK内部还可能重试，不能把逻辑调用数当HTTP请求数。失败token用量未知，没有填成0。失败不作为语义质量失败，也没有把失败记录覆盖成成功。不能报告“反馈重复2/2成功”或仅统计成功请求而隐藏可用性问题。

## 复现

从backend目录用新输出路径执行：

```powershell
uv run python -m research.plan_feedback_experiment --baseline benchmark_runs/glm47flash-planner-no-thinking-pilot-2026-10-08.json --output benchmark_runs/feedback-new-run.json
```

只补一次供应商失败，不重新调用成功组：

```powershell
uv run python -m research.plan_feedback_experiment --baseline benchmark_runs/glm47flash-planner-no-thinking-pilot-2026-10-08.json --retry-run benchmark_runs/feedback-new-run.json --retry-condition feedback_2 --output benchmark_runs/feedback-new-retry.json
```

不能针对已经成功或产生无效计划的条件选择性重跑直到满意。成功的计划、技术格式失败和供应商拒绝都需要保留。采样脚本的退出状态为非零，因为计划内第二次反馈观察尚未取得；退出非零不抹掉已经取得的成功配对。

## 验证与结论边界

- 后端全量：747 passed、2 skipped、22 subtests passed（76.82秒）。
- 6个新增实验测试覆盖共同上下文、反馈隔离、冻结prompt、独立历史、无效计划、失败保留、精确单条件重试与不泄漏异常正文。
- Ruff通过；mypy检查67个源文件通过；新增文件格式检查通过。
- 评审中的任务文本与实际响应核对一致，标签通过既有schema；未修改生产门禁。

本次支持继续验证“明确反馈可补足计划目标”这一方向。只有一个主题、一个成功反馈观察；条件顺序未随机化；提出反馈与复评的是同一AI，且反馈直接提示了rubric缺口。不能推断泛化收益、统计显著性、盲评准确率、真实研究质量或稳定延迟。在线语义Judge和Embedding均未接入。

下一轮应在供应商恢复后补足重复，并在其他开发主题上使用事先冻结的评估标准，再决定提示词调整或独立Judge实验。
